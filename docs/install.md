# Установка

Content Factory - система на Markdown-файлах. Ей не нужна сборка.

Разные агентные инструменты ожидают разные имена папок. В этом репозитории по умолчанию используются нейтральные папки:

```text
agents/
skills/
templates/
docs/
examples/
```

## Универсальное использование

Файлы можно использовать напрямую:

1. Прочитать `README.md`.
2. Заполнить шаблоны.
3. Передать нужные инструкции своему ИИ-инструменту.
4. Запустить конвейер из подходящего `skills/write-*`.

## Настройка в стиле Claude Code

Claude Code — референсная среда запуска: система рассчитана на его подагентов и скиллы и тестируется в нем.

Если инструмент ожидает Claude-папки, предпочтительно связать их символическими ссылками, а не копировать:

```bash
mkdir -p .claude
ln -s ../agents .claude/agents
ln -s ../skills .claude/skills
```

Симлинк — это ярлык: у файлов остается один источник истины, и скиллы, которые меняют систему (`learn`, `new-format`), правят сразу «живые» копии. Если вместо симлинков делаете копии — после каждого изменения скиллов синхронизируйте обе стороны вручную.

Затем оставьте `AGENTS.md` или создайте `CLAUDE.md` с теми же проектными инструкциями.

Скиллы ссылаются друг на друга по путям от корня системы (`skills/good-writing/SKILL.md`, `examples/`, `output/`), поэтому рабочей директорией при запуске должен быть корень Content Factory. Если запустить конвейер из другой папки, `pipeline-core.md` найдет правила сам (см. «Глобальная установка»).

## Глобальная установка: писать из любого проекта

Система умеет работать и не из своего репозитория. Скопируйте или слинкуйте скиллы и агентов в пользовательские папки:

```text
skills/  -> ~/.claude/skills/
agents/  -> ~/.claude/agents/
```

Тогда `write-*` скиллы можно запускать из любой папки. При запуске `pipeline-core.md`:

- правила и роли берет из `~/.claude/skills/` и `~/.claude/agents/` (корень системы);
- материалы проекта — профиль, примеры, исходники, результаты — держит в папке `content-project/` текущей директории (рабочее пространство) и создает ее при первом запуске;
- профиль проекта при первом запуске заполняет сам: сканирует `CLAUDE.md`, `README.md`, брендбуки, а недостающее спрашивает у пользователя.

Так один набор правил обслуживает несколько проектов, а материалы каждого проекта живут внутри самого проекта.

## Если копии, а не симлинки

Симлинки решают синхронизацию сами собой. Но копии заводят по разным причинам: поставка скиллов в составе пакета, машина без прав на ссылки, отдельный набор под один проект. Копии разъезжаются: правку внесли в одном месте, второе про нее не знает.

Для этого случая есть скрипт.

```bash
scripts/sync-skills.sh
```

Без флагов он ничего не меняет: показывает, какие файлы в целях отличаются от репозитория, и выходит с ненулевым кодом, если расхождения есть. Так его удобно повесить на git-хук или в CI.

```bash
scripts/sync-skills.sh --apply
```

Переносит файлы из репозитория в цели. Цель по умолчанию одна — `~/.claude` (меняется переменной `CLAUDE_HOME`). Дополнительные цели передаются аргументами: любой каталог, внутри которого лежат `skills/` и `agents/`.

```bash
scripts/sync-skills.sh --apply ~/projects/my-package/plugins/my-plugin
```

Два правила, которые стоит знать:

- В дополнительные цели переносятся только файлы, которые там уже есть. Пакет с частью скиллов не получит остальные.
- Файл, который в цели новее, чем в репозитории, не перезаписывается. Скорее всего, его правили руками и правка еще не вернулась в репозиторий: скрипт скажет об этом и выйдет с кодом 2. Такие файлы разбираешь сам — репозиторий остается источником истины, но затирать чужую работу молча скрипт не будет.

## Настройка в стиле Codex и других раннеров

Если инструмент читает `AGENTS.md`, оставьте корневой `AGENTS.md` как главную инструкцию.

Если настройка поддерживает пользовательские скиллы, скопируйте или свяжите:

```text
skills/ -> .agents/skills/
```

Точная папка зависит от раннера.

Важно про подагентов: конвейер описан для среды с подагентами (researcher, planner, writer — отдельные роли со своими инструкциями в `agents/`). Если ваш раннер подагентов не поддерживает, конвейер все равно выполним: агент проходит этапы последовательно сам, перед каждым этапом читая файл соответствующей роли из `agents/` и следуя ему. Качество будет чуть ниже (один контекст на все роли), но процесс и правила сохраняются.

## Первый запуск

Создайте рабочую папку:

```text
output/test-run/
```

Подготовьте:

- заполненный профиль проекта;
- заполненный профиль формата;
- редполитику одного формата;
- один исходник в `input/`;
- 2-3 примера.

Затем запустите редакционный конвейер:

```text
исследование, если нужно -> план -> проверка плана -> согласование -> черновик -> финальная редактура
```

## Что коммитить

Коммитить:

- агентов;
- скиллы;
- документы;
- шаблоны;
- нейтральные примеры;
- пустой `input/.gitkeep`;
- пустой `output/.gitkeep`.

Не коммитить:

- реальные исходники;
- сгенерированные черновики;
- финальные тексты;
- локальные настройки;
- приватные заметки;
- секреты.
