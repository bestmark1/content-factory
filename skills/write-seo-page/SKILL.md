# Создание SEO-страницы

Бриф: $ARGUMENTS

Общий процесс описан в pipeline-core.md — файл лежит в папке со скиллами, уровнем выше папки этого скилла (skills/pipeline-core.md в репозитории, ~/.claude/skills/pipeline-core.md при глобальной установке). Прочитай его целиком и выполняй шаги оттуда. Ниже параметры и специфика этого формата.

## Параметры формата

- Тип контента: seo-page
- Ред-политика: skills/redpolicy-seo-page/SKILL.md
- Папка с примерами: examples/seo-pages/
- Имя рабочей папки: слаг из целевого запроса

Перед стартом определи из брифа: целевой запрос, тип страницы (product-led / сравнение / ситуация), CTA-сценарий (какое действие в продукте продолжает страницу). Чего-то не хватает — спроси у пользователя сейчас, а не в середине.

## Исследование: нужно

Используй подагента **researcher**. Передай ему: целевой запрос, тип страницы, рабочую папку, профиль проекта.

Дополнительные инструкции для researcher:
- **Выдача по запросу:** разбери 3–5 страниц из топа — структура, что закрывают, чего не хватает. Это референсы для планировщика, не для копирования.
- **Соседние подзапросы:** собери 5–10 формулировок, которыми люди спрашивают то же самое и рядом (подсказки поиска, «люди также спрашивают», формулировки с форумов). Каждая — кандидат в H2.
- **Живые боли:** найди на форумах и в обсуждениях, как люди своими словами описывают проблему запроса. Дословные формулировки фиксируй в research.md — они пойдут в H2 и FAQ.
- **Факты и цифры:** статистика по теме с URL источника и датой. Для страниц-сравнений — проверенные лимиты и поведение сравниваемого продукта, тоже с датами.
- **Для ситуационных страниц:** корректные местные фразы по сценарию с транскрипцией — с проверкой по двум источникам.

## Семантика: нужна

Обязательный шаг для этого формата. Структура страницы строится от кластеров и вопросов из semantics.md, подзаголовки — из живых формулировок запросов. Проверь, что интент кластеров совпадает с типом страницы: под запрос «как сделать X» продуктовая страница не встанет.

## Интервью: по желанию

Классическое интервью с экспертом этому формату не нужно: продуктовая страница говорит от лица компании, а не от лица автора с личным опытом. Личных историй тут не будет.

Спрашивай, только если в research.md не хватает данных о самом продукте, которых нет в открытом доступе: реальные сценарии клиентов, возражения из переписок и звонков, цифры продукта, чем он проигрывает альтернативам. Хватает исследования и брифа — шаг пропускай, не задавай вопросы ради процесса.

## Планирование — дополнительные инструкции для planner

- Каждый блок = один подзапрос из research.md; H2 — вопросом, живой формулировкой.
- Первый блок плана — лид: прямой ответ на запрос в 40–60 слов.
- Заложи минимум одну таблицу фактов и укажи, какие данные из research.md в нее идут.
- Карта CTA: после каких блоков повторяется главный CTA и как он сформулирован в каждом месте.
- FAQ-блок: 3–5 вопросов из живых формулировок research.md, включая возражения (цена, интернет, качество).

## Проверка плана — специфика формата

- Message match: H1 и лид отвечают именно на целевой запрос, а не на соседний?
- Интент закрыт: человек с этим запросом найдет все, за чем пришел, или придется возвращаться в поиск?
- Все подзапросы из research.md либо покрыты блоками, либо осознанно отброшены?
- CTA-сценарий сквозной: каждый CTA продолжает то, что читатель делал на странице?

## Требования к writer

- Лид и первые два предложения каждой секции — самодостаточный ответ (см. ред-политику: их извлекают сниппеты и цитируют LLM).
- Цифры только из research.md, с источником и датой в тексте.
- Копия CTA называет ценность и сценарий, не действие.
- Фразы с озвучкой — по шаблону ред-политики, аудио — плейсхолдером `[аудио: слаг-фразы]`.
- Никакого выдуманного social proof и непроверенных цифр.
- Не использовать букву с двумя точками; antipatterns.md — инструмент для сомнительных мест, не чек-лист.

## Финальная проверка — специфика формата

Дополнительные слои: факты о конкурентах против research.md (с датами); фразы против research.md; запрос не переспамлен (читай вслух — звучит по-человечески?).

Вместо двух общих целевых проходов — три:
- **AEO-проход.** По каждому H2: это вопрос живой формулировкой? Первые два предложения после него — самодостаточный ответ, который можно вырвать и процитировать? Лид укладывается в 40–60 слов и отвечает на запрос целиком?
- **CRO-проход.** Тест пяти секунд: посмотри только на H1, лид и первый CTA — понятно, что это, для кого и что делать дальше? Каждый CTA — ценность и продолжение сценария? Возражения закрыты в FAQ?
- **Чтение вслух.** Каждый абзац: «коллеге за кофе так бы объяснил?» Каталожное и рекламное — переписать целиком.
