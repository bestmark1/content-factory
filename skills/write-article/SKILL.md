# Создание статьи-подборки сервисов

Исходный материал: $ARGUMENTS

Общий процесс описан в pipeline-core.md — файл лежит в папке со скиллами, уровнем выше папки этого скилла (skills/pipeline-core.md в репозитории, ~/.claude/skills/pipeline-core.md при глобальной установке). Прочитай его целиком и выполняй шаги оттуда. Ниже параметры и специфика этого формата: применяй их в отмеченных местах общего процесса.

## Параметры формата

- Тип контента: article
- Ред-политика: skills/redpolicy-article/SKILL.md
- Папка с примерами: examples/articles/
- Имя рабочей папки: из имени исходного файла

## Исследование: нужно

Используй подагента **article-researcher**. Передай ему: путь к исходнику ($ARGUMENTS), рабочую папку.

Результат: research.md с актуальными данными о каждом сервисе. Дальше все агенты и проверки используют ОБА файла — исходник и research.md; данные из research.md актуальнее.

## Семантика: по желанию

Спроси пользователя. Для подборки семантика помогает, когда непонятно, как люди называют эту группу сервисов: «нейросети для видео» и «AI генератор видео» — это два разных набора запросов и два разных списка сервисов.

## Интервью: нужно

Спрашивай про личный опыт с сервисами из подборки: чем реально пользовался, что бросил и почему, где уперся в лимиты, за что платит деньгами. Это единственное, чего нет на сайтах самих сервисов.

## Проверка плана — специфика формата

- Каждый сервис заложен по шаблону: название, ссылка, стоимость, описание?
- Данные в плане совпадают с research.md? Цены и статусы не взяты из устаревшего исходника?
- Подборка логично упорядочена, нет сервисов-дублей с одинаковой ролью без объяснения разницы?
- Перегруз деталями тарифов и ограничений вычеркивай (см. antipatterns.md, раздел «Избыточные детали в описании сервисов»).

## Требования к writer

- Шаблон описания сервиса по ред-политике; ссылка на каждый сервис.
- Не использовать букву с двумя точками.
- antipatterns.md — не чек-лист, а инструмент для сомнительных мест.

## Финальная проверка — специфика формата

Дополнительные слои проверки:
- **Шаблон сервиса.** Каждый сервис: название, ссылка, стоимость, описание. Ссылки на месте и вшиты в название, а не голым доменом.
- **По antipatterns.md особенно:** разделы «Избыточные детали в описании сервисов», «Перегруженные цены», «Маркетинговый тон».
- **Дубли.** Стоимость не повторяется в описании; одинаковые формулировки не кочуют из сервиса в сервис.

Формулировки двух целевых проходов для этого формата:
- **Охота на балласт.** По каждому предложению: «поможет ли это читателю выбрать сервис?» Нет — удаляй.
- **Чтение вслух.** Каждое описание: «так бы посоветовал сервис коллеге?» Каталожное и рекламное — переписать целиком.
