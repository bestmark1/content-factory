# Общий конвейер write-скиллов

Это общая часть всех оркестраторов `write-*`. Скилл формата, который тебя запустил, задает параметры и специфику: тип контента, ред-политику, папку примеров, дополнительные проверки. Здесь описан скелет процесса, одинаковый для всех форматов. Читай так: шаги — отсюда, вставки «специфика формата» — из скилла формата.

## Сначала найди корень системы

Все пути в конвейере (skills/, agents/, examples/, output/) отсчитываются от корня Content Factory — папки, в которой лежит skills/good-writing/SKILL.md. Проверь, что этот файл виден из текущей директории. Если нет — найди его через Glob (`**/skills/good-writing/SKILL.md`) и используй найденную папку как корень для всех путей. Не нашел — остановись и спроси пользователя, где лежит система.

## Что важно понимать про процесс

Главный инструмент качества — **твоя проверка в основном контексте**, не агенты. Раньше в цепочке были агенты `plan-checker`, `text-checker`, `final-reviewer` — они вылизывали текст по чек-листам и делали его механическим, не видя полной картины. Теперь эти этапы делаешь ты: читаешь и правишь сам. Ты видишь весь текст целиком, помнишь историю разговора с пользователем и знаешь примеры — поэтому именно ты ловишь книжные конструкции, дубли и расхождения с фактурой.

Перед тем как писать — прочитай 1–2 текста из папки примеров формата, если они есть. Стиль формируется из примеров, а не из правил. Если примеров нет, работай по ред-политике и профилю проекта.

## Рабочая папка

1. Возьми основу имени из аргумента скилла. Для форматов с исходником — имя файла без пути и без расширения .md. Для форматов без исходника (тема вместо файла) — короткое имя из темы: транслит или ключевые слова, без пробелов, через дефис.
2. Рабочая папка: output/[имя]/. Создай ее командой: mkdir -p output/[имя]/
3. Все агенты сохраняют файлы в эту рабочую папку. Передавай путь к ней каждому агенту.

## Шаг «Исследование» (если формат его требует)

Скилл формата говорит, нужен ли этот шаг, какой агент его выполняет (researcher или article-researcher) и какие дополнительные инструкции ему передать. Результат всегда один: файл research.md в рабочей папке. Если research.md есть, дальше все агенты и проверки используют ОБА источника — исходник и research.md; данные из research.md актуальнее. Если шаг формату не нужен — пропусти его.

## Шаг «Планирование»

Используй подагента **planner**. Передай ему:
- путь к исходнику и путь к research.md, если он есть (с пометкой, что данные из research.md актуальнее)
- тип контента и путь к ред-политике (из скилла формата)
- рабочую папку
- путь к папке с примерами (прочитать 1–2 примера перед составлением плана)
- дополнительные инструкции из раздела «Планирование» скилла формата, если они там есть

Результат: файл plan.md в рабочей папке.

## Шаг «Проверка плана» (ты в основном контексте)

**Агент plan-checker больше не используется.** Проверяешь план сам.

1. Прочитай plan.md целиком, держа рядом research.md, если он есть.
2. Прочитай 1–2 примера формата, если еще не читал, — чтобы помнить целевую структуру.
3. Общие проверки для любого формата:
   - К каждому блоку: «можно ли его убрать без потери пользы для читателя?» Блоки-наполнители вычеркивай.
   - К каждому факту: «зачем это читателю?»
   - Нет ли дублей между блоками: один тезис или факт — одно место.
4. Прогони проверки из раздела «Проверка плана» скилла формата.
5. При необходимости переписывай план сам — не запускай обратно агента. Ты работаешь быстрее и не ломаешь собранную фактуру.

## Шаг «Согласование плана»

Покажи пользователю plan.md и расскажи коротко, что поменял после своей проверки. Спроси, одобряет ли план.

- Если одобряет — переходи к следующему шагу.
- Если просит изменения — внеси правки в plan.md и покажи обновленную версию.
- НЕ НАЧИНАЙ писать текст, пока план не будет явно одобрен словами типа «ок», «давай», «пиши», «одобряю».

## Шаг «Написание по блокам»

Прочитай утвержденный plan.md и найди все пронумерованные блоки. Разбей на пары: [1–2], [3–4], [5–6] и т.д. Если блоков нечетное число — последняя группа из одного блока.

Для каждой пары последовательно запускай подагента **writer**. Каждый следующий запускается только после завершения предыдущего.

Каждый writer получает:
1. Путь к исходнику и путь к research.md, если он есть (данные из research.md актуальнее)
2. Тип контента и путь к ред-политике (из скилла формата)
3. Правила письма: skills/good-writing/SKILL.md и skills/good-writing/antipatterns.md
4. **Эталон стиля в промпте:** если в папке примеров формата есть тексты, 2–3 подходящих фрагмента встрой прямо в промпт как образец вайба. Не «прочитай файл», а готовый текст в промпте — иначе агент не проникнется стилем.
5. Рабочую папку
6. Полный план: [рабочая папка]/plan.md (чтобы агент понимал траекторию всего текста)
7. Уже написанный текст: содержимое [рабочая папка]/draft.md (пустое для первой пары; нарастает с каждой итерацией)
8. Задание: «напиши блоки X и Y, добавь в конец [рабочая папка]/draft.md»
9. Обязательные требования из раздела «Требования к writer» скилла формата

Агент не перезаписывает draft.md — только дописывает в конец. После всех пар draft.md содержит полный черновик.

## Шаг «Финальная проверка» (ты в основном контексте)

**Агенты text-checker и final-reviewer больше не используются.** Проверяешь и финализируешь сам.

1. Прочитай draft.md целиком, держа рядом исходник и research.md, если он есть.
2. Общие слои проверки:
   - **Факты против фактуры.** Цифры, цены, названия и утверждения совпадают с исходником и research.md; ничего не додумано сверх них.
   - **Соответствие ред-политике формата:** структура, лид, финал.
   - **Без буквы с двумя точками** по всему тексту.
   - **Книжные конструкции и нейромаркеры** по skills/good-writing/antipatterns.md — для сомнительных мест, не как протокол.
   - **Дубли** между блоками; выводы-обобщения, повторяющие сказанное.
   - **Сравнение с примерами.** Открой 1–2 текста формата и сверь подачу.
3. Прогони дополнительные слои и целевые проходы из раздела «Финальная проверка» скилла формата.
4. Сделай два общих целевых прохода — по одному паттерну за раз (если скилл формата дает свои формулировки этих проходов, используй их):
   - **Охота на балласт.** По каждому предложению: «без него смысл пострадает?» Не пострадает — удаляй.
   - **Чтение вслух.** Каждый абзац: «коллеге за кофе так бы объяснил?» Книжное — переписать целиком, не подправлять слово.
5. Вноси правки напрямую через Edit. Не делегируй агенту — он сломает стиль вылизыванием.
6. Скопируй итог в [рабочая папка]/final.md.

## Шаг «Сдача»

Покажи пользователю [рабочая папка]/final.md и краткий отчет о правках, которые ты внес на финальной проверке. Спроси, устраивает ли результат или нужны доработки.

## Выполняй шаги последовательно

Каждый следующий шаг начинается только после полного завершения предыдущего.

Проверка плана и финальная проверка — это **твоя работа в основном контексте**, а не вызов агента. Не делегируй их обратно агентам `plan-checker`/`text-checker`/`final-reviewer` — архитектура осознанно построена так, что ты делаешь эти этапы сам.
